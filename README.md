# Экспертная система подбора направления в КФУ

Продакшн-версия экспертной системы для подбора образовательных программ в Казанском Федеральном Университете.

## 🚀 Возможности

- **Умный подбор программ**: Система анализирует интересы, способности и цели абитуриента для подбора наиболее подходящей образовательной программы
- **Обработка всех сценариев**: Система работает как с абитуриентами, которые уже сдали ЕГЭ, так и с теми, кто еще не сдавал
- **Рекомендации по ЕГЭ**: Для абитуриентов, которые еще не сдали ЕГЭ, система подсказывает, какие экзамены нужно сдать для выбранных направлений
- **Персонализированные вопросы**: Генерация индивидуальных вопросов на основе ответов абитуриента
- **Альтернативные программы**: Возможность получить дополнительные варианты программ

## 📋 Требования

- Python 3.8+
- Telegram Bot Token
- API ключи для LLM (Yandex GPT, Qwen или Gemini)

## 🔧 Установка

1. Клонируйте репозиторий или скачайте файлы проекта

2. Установите зависимости:
```bash
pip install -r requirements.txt
```

3. Создайте файл `.env` на основе `.env.example`:
```bash
cp .env.example .env
```

4. Заполните `.env` файл своими данными:
   - `TELEGRAM_BOT_TOKEN` - токен вашего Telegram бота (получить у @BotFather)
   - `YANDEX_FOLDER_ID` и `YANDEX_AUTH_TOKEN` - для Yandex GPT
   - `QWEN_API_KEY` - для Qwen API (опционально)
   - `GEMINI_API_KEY` - для Gemini API (опционально)
   - `DEFAULT_LLM_MODEL` - модель по умолчанию (yandex, qwen или gemini)

## 🏃 Запуск

```bash
python bot.py
```

Бот начнет работать и будет отвечать на сообщения в Telegram.

## 🎯 Как это работает

1. **Старт**: Пользователь запускает бота командой `/start`
2. **Опрос**: Бот задает вопросы о интересах, целях и успеваемости
3. **ЕГЭ**: Бот спрашивает о статусе ЕГЭ:
   - Если ЕГЭ уже сданы → запрашивает список экзаменов и баллы
   - Если ЕГЭ еще не сданы → после выбора направления покажет рекомендации по необходимым ЕГЭ
4. **Выбор направления**: Пользователь выбирает интересующую область
5. **Персональные вопросы**: Система генерирует индивидуальные вопросы на основе ответов
6. **Подбор программы**: LLM анализирует все данные и подбирает наиболее подходящую программу
7. **Альтернативы**: Пользователь может запросить дополнительные варианты

## 🔐 Безопасность

- Все токены и ключи хранятся в переменных окружения (файл `.env`)
- Файл `.env` не должен попадать в систему контроля версий (добавлен в `.gitignore`)
- Логирование всех действий для отладки и мониторинга

## 📝 Логирование

Логи сохраняются в файл `bot.log` и выводятся в консоль. Уровень логирования настраивается через переменную `LOG_LEVEL` в `.env`.

## 🛠️ Разработка

### Добавление новых направлений

Отредактируйте словарь `DIRECTION_TO_INSTITUTES` в файле `bot.py`.

### Изменение требований по ЕГЭ

Отредактируйте словарь `INSTITUTE_EXAMS` в файле `config.py`.

### Добавление новых программ

Добавьте программы в файл `kfu_programs_by_institute.json` в соответствующем формате.

## 🐳 Деплой (Docker + GitHub Actions)

Автодеплой при пуше в `main`/`master`: сборка образа → пуш в GitHub Container Registry (ghcr.io) → деплой на ВМ по SSH.

### Что в репозитории

- `Dockerfile` — сборка образа бота
- `docker-compose.yml` — запуск контейнера (образ подставляется из CI: `IMAGE`/`TAG` для GitHub, `CI_REGISTRY_IMAGE`/`CI_COMMIT_SHORT_SHA` для GitLab)
- `.github/workflows/deploy.yml` — workflow: сборка и пуш в GHCR, затем деплой на ВМ по SSH

### 1. Настройка репозитория на GitHub

1. **Secrets** (Settings → Secrets and variables → Actions): создайте секреты:
   - `DEPLOY_HOST` — IP или hostname ВМ
   - `DEPLOY_USER` — пользователь для SSH (например `deploy` или `root`)
   - `DEPLOY_SSH_KEY` — приватный SSH-ключ для доступа к ВМ (полное содержимое ключа, включая `-----BEGIN ... KEY-----`)
   - `DEPLOY_PATH` (опционально) — каталог на ВМ с `docker-compose.yml` и `.env` (по умолчанию `/opt/kpfu-bot`)
   - `DEPLOY_PORT` (опционально) — порт SSH, если не 22

2. **Права для GITHUB_TOKEN**: по умолчанию workflow имеет доступ к записи в Packages (GHCR). Для приватного репозитория при необходимости выдайте права **Actions: read**, **Packages: read** (для шага deploy).

### 2. Подготовка ВМ

На сервере, куда деплоите:

1. **Docker и Docker Compose**:

   ```bash
   # Ubuntu/Debian
   sudo apt update && sudo apt install -y docker.io docker-compose-plugin
   sudo usermod -aG docker $USER
   # выйти и зайти снова или: newgrp docker
   ```

2. **Каталог деплоя**:

   ```bash
   sudo mkdir -p /opt/kpfu-bot
   sudo chown $USER:$USER /opt/kpfu-bot
   cd /opt/kpfu-bot
   ```

3. **Файлы на ВМ** (один раз):
   - Скопируйте `docker-compose.yml` из репозитория в `/opt/kpfu-bot/`
   - Создайте `/opt/kpfu-bot/.env` по образцу `env_example.txt` и заполните токены и ключи

4. **SSH-доступ**: пользователь из `DEPLOY_USER` должен входить по ключу (тот, чей приватный ключ лежит в `DEPLOY_SSH_KEY`) и иметь права запускать `docker` (в группе `docker`).

### 3. Как работает автодеплой

При **push** в `main` или `master`:

1. **build** — собирается Docker-образ, пушится в `ghcr.io/<owner>/<repo>:` с тегами короткого SHA и `latest`.
2. **deploy** — по SSH на ВМ выполняются: логин в GHCR, `docker compose pull`, `docker compose up -d`. Образ берётся как `IMAGE`/`TAG` (для GitHub — `ghcr.io/.../...:latest`).

Если секреты деплоя не заданы, шаг deploy упадёт с ошибкой — можно отключить деплой, закомментировав job `deploy` в `.github/workflows/deploy.yml`.

### 4. Локальный запуск через Docker

```bash
# Сборка
docker compose build

# Запуск
IMAGE=kpfu-edu-bot TAG=latest docker compose up -d
```

В каталоге должен быть `.env` (по образцу `env_example.txt`).

### 5. GitLab (альтернатива)

Если используете GitLab, в репозитории есть `.gitlab-ci.yml`: сборка и пуш в GitLab Container Registry, деплой раннером с тегом **deploy** на ВМ. На ВМ нужен GitLab Runner (shell executor) с тегом `deploy` и каталог с `docker-compose.yml` и `.env`. Переменные образа для GitLab: `CI_REGISTRY_IMAGE`, `CI_COMMIT_SHORT_SHA` (уже учтены в `docker-compose.yml`).
